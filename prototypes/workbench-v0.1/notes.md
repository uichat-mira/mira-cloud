# Mira Cloud 统一工作台 — 产品原型说明 v0.1

> 2026-11-11 · 概念原型 · 未接生产 · 已通过本地交互模拟与桌面/移动布局检查

## 产品目标

用户不需要理解内部 Agent/Scheduler/Runtime 结构，只需要知道：**我交代了什么工作、它何时执行、执行得怎样、留下了什么成果、能否继续推进**。

Mira Cloud Account 是身份与工作台入口；Cloud Pi 是任务与执行事实源；Relay 是传输；Desktop Host 的本地能力仍然由 Host 自身授权与执行。

## 信息架构

1. **工作台总览**：执行中、启用计划、历史运行、成果数；最近运行；未来计划；快速委托；最近成果。
2. **临时委托**：输入名称、目标、允许的能力范围、期望成果；创建一次有独立 Run ID 的工作。
3. **定时任务**：定义工作目标、周期、时区、执行时间与可信投递目的地；支持启停、编辑与立即执行；计划不覆盖历史。
4. **运行记录**：按状态检索；单次运行保留 runId、来源、开始/结束、结果、失败和产物引用；部分完成与成功区分。
5. **成果库**：按来源与类型查阅报告/笔记；阅读、复制、导出 Markdown、以成果启动新委托。
6. **能力与权限**：展示服务边界；不把公开 IM 聊天资格当作用户的私有工具权限。

## 核心体验闭环

**临时委托 → Run → Artifact → 继续委托**。计划任务则由 **Schedule → Trigger → Run → Artifact** 复用同样的执行与成果呈现。一个 Schedule 可对应多次 Run；每次 Run 只能拥有一个真实执行所有者；Artifact 记录来源 Run、版本和访问主体。

## 现有工程可复用部分（依据 2026-11-11 读取的 dev 分支）

- Cloud Auth `apps/web/src/pages/account/cloud-agent-page.tsx`：已有 `/agent-control` 代理下状态、计划与最近运行展示；计划暂停、启用、立即执行。
- Cloud Pi `src/api/contracts.mjs`：管理 API 路径 `/v1`，loopback 监听；已定义运行列表、报告、投递状态相关边界。
- Cloud Pi `src/scheduler/contracts.mjs`：`once` / `recurring`、`active` / `paused` / `completed`、可信 `deliveryTargets` 与时区语义。
- Cloud Pi 的 Scheduler、Run Store、Delivery Store 各自保有业务事实，不应被 Portal 复制一套。

## 需要设计与实现的缺口（均未声称已接通）

- **通用临时任务入口**：现有 IM `/research` 并不等于 Portal 上面向授权用户的通用任务创建合同。需确定创建请求、权限、成本上限、幂等键、异步返回及取消语义。
- **前端计划 CRUD**：现有 Cloud Auth 页面仅调用 `GET`/`POST`，没有完整的创建/编辑/删除体验及请求体支持；需按既有 Cloud Pi API 合同接线，而不是新建任务数据表。
- **成果索引**：当前研究 Run 产物以 Run Store 方式持久化；“跨所有 Run 的成果库”需要经过授权的索引/查询投影、分页、检索与格式读取；不必立即引入对象存储。
- **跨云节点**：若 Cloud Pi 迁至腾讯云，当前 Owner Gateway 的 Cloud Auth 与 Agent loopback 同机依赖需要明确、受限的跨节点调用合同，不应直接暴露内网 API。
- **可观测与权限**：真实状态需要按 Run ID 回放，报告研究成功和消息投递成功是两个不同事实；公开 IM 使用者不得继承 Owner 的私有权限。

## 原型交互清单

- 新建临时委托：创建演示任务/Run，模拟完成，生成可追踪成果。
- 新建或编辑计划：支持周期、时间、时区、投递位置；可暂停/恢复和模拟立即执行。
- 运行记录：支持搜索、状态筛选、展开查看执行轨迹与关联成果。
- 成果库：支持搜索、类型筛选、阅读、复制、下载 Markdown 和以成果再次委托。
- 数据保存在当前浏览器的 localStorage（可一键重置）。**没有生产网络请求、真实模型费用、IM 投递、真实 MCP 或鉴权**。

## 验收重点（未来接线时）

1. 未认证/跨账户请求拒绝；账户与 Agent 业务状态不相互复制。
2. 一次委托产生唯一 Run，刷新页面后可恢复状态，不因刷新重复执行。
3. 同一计划的每次触发得到不同 Run；时区、DST、错过触发、重启补跑可解释。
4. 执行成功、部分完成、失败、取消与投递失败可分别呈现。
5. Artifact 不能凭猜测路径或跨账户访问；删除/撤权后的可见性明确。
6. 真实外部发送、写入或昂贵任务必须经过适当确认与费用/权限限制。
7. 手机和桌面均能完成创建、查看、恢复、成果复用的主流程。

## 后续迭代

**Memory / Skills / MCP 管理** 应作为下一阶段深入研究，不在当前原型中伪造可用性。优先使工作与成果可追溯，之后再让记忆从可信 Run 和用户明确偏好中提炼。
