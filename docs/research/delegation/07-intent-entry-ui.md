# 07 · D02 意图进入与需求草稿起稿原型

**状态**：Mac 本地 /new 交互原型，等待用户视觉验收；尚未提交远程。
**依据**：[「交代工作」Intelligent UI PRD §3.1 / D02](../../product/delegation-intelligent-ui.md)、[Workbench IA](../../product/workbench.md)、[第一轮审阅 UI](./06-inline-review-ui.md)。

## 用户路径（已在本地原型中接线）

1. /new 无有效本地草稿时，先展示「有什么事，想交给 Mira？」意图输入。**不自动生成行业研究 Fixture**，不要求先填写计划、周期、模型、权限或表单。
2. 用户明确提交一句意图后，进入短暂的本地模板准备状态；可以取消且不会保存半成品。**准备不是 AI 网络请求**。页面明确声明只生成演示草稿。
3. 草稿包括用户原文的 Markdown 引用、通用「工作目标 → 工作节奏 → 交付与边界」三个演示阶段以及绑定 json-render 的可编辑确认控件。后续审阅、批注和验收沿用现有页面，不生成新的审阅工具树。
4. 可选的三个示例是显式演示入口。若从 /artifacts/:id 的已知 Fixture 成果详情发起 /new，入口会展示该示例成果的**标题与版本**，用户可明确点击「以此起稿」。此路径**不读取 Artifact 正文**、不使用真实 ACL，也不代表取得了可靠云端上下文。
5. 生成后的演示草稿存于当前浏览器标签页 sessionStorage；刷新时恢复原画布而不是再问一次。用户点击「新交代」须确认才放弃已有草稿并返回意图输入。

## 一致性与失败边界

- 自由输入不会被无声替换成 AI 雷达、旅行或创业示例；使用独立通用 custom 场景，保留用户输入的原文与语义。
- 起稿前不写入委托草稿。浏览器存储失败则返回可重试的错误提示，保留刚刚填写的意图，不伪称任务已创建。
- 用户输入中的 Markdown 标题作为引文保存，不能篡改「当前约定」的单一结构，因此正文与 json-render 控件仍能校验一致。
- 该版本仍使用三个模板阶段，**尚无 AI 判断阶段数量、上下文提取、真实流式生成或实际创建 Task**。真实生成、网络故障重试、证据来源、已授权 ArtifactRef 与 Cloud Auth/Pi 的联调属于后续独立工程验证。
- 本地页面 URL 的 fixture=radar 等参数仅在 Vite 开发模式开放，供现有 CDP 回归跳过首次入口；正式构建不允许此参数绕过 D02 起点。

## 验证

- Vitest：首次入口为空、自由语言起草并恢复、显式示例、演示成果入口、取消、存储失败重试、放弃草稿确认；单文档测试验证用户提供 Markdown 标题的结构安全与控件同步。
- 实际 Mac Chrome：[intent-entry-qa.mjs](../../../prototypes/delegation-inline-review/intent-entry-qa.mjs)，覆盖初始无草稿、输入后准备态、完成后原话出现在第一阶段、刷新恢复、确认重置，以及 390 / 320 / 270px 无横向溢出。
- 旧有九条随文批注/版本/吸顶/独立滚动回归继续在明确的 QA Fixture 路由上执行，避免把「入口已改变」误判成批注退化。
- 一切证据都是本地 Fixture 体验，**不等同真实生成或长期任务提交能力**。
