# Diff 集中修订 UI 接线与浏览器验证

**日期**：2026-11-17
**范围**：将 09 阶段验证过的本地修订候选模型接入正式 /new 交互页面；只验证 UI 与本地状态闭环，不接真实模型或云端运行时。

## 1. 本轮实现

- 在现有单一需求文档内展示修订候选，不新增第二套审阅页面或任务状态机。
- 使用本地 Fixture 生成预设变更；经修订候选校验后，先展示候选，用户明确采用后才写入当前草稿。
- 正文 Diff 复用 ProseMirror 文字差异能力；结构化字段 Diff 通过已登记字段 ID 对比，不做像素级 UI Diff。
- 候选与正式草稿分离。采用前不改正文、字段、批注状态或版本号；采用后一次只增加一个修订版本，并保存原始来源快照。
- 批注处理建议与状态一并保存。suggested 仅表示本地演示建议，用户仍需逐条确认解决或放弃；未处理批注继续阻断阶段验收。
- 历史批注只回看其原始来源版本，不把旧锚点猜测映射到新版。
- Diff 面板和修订引擎按需加载。手机端在 Diff 组件实际挂载后滚动到候选区域，避免批注底部面板遮挡主要内容。

## 3. 明确边界

本轮是本地 Fixture UI 原型，不是 AI 或生产能力：

- 修订候选由预设 Fixture 生成，不理解自然语言批注，不代表模型生成质量。
- “生成中”是本地演示节奏，不是 SSE、模型流式响应或真实服务端任务。
- 草稿仍使用 sessionStorage；没有跨设备同步、云端持久化、并发版本锁或服务端提交。
- 文本 Diff 以段落文字为单位；复杂 Markdown 结构、富文本行内格式和跨版本行内锚点尚未完成浏览器级验收。
- 结构化 Diff 只覆盖已登记字段；动态组件级锚定仍未实现。
- 手机验证是 390px Chrome 模拟视口，不等同于 iOS/Android 真机、软键盘和完整 Safe Area 验收。
- Cloud Auth、Cloud Pi Scheduler、Run、Delivery 和长期工作生命周期均未接入或验收。

## 4. 后续验证方向

1. 继续完成 Markdown 复杂结构与版本锚点的可靠性验证。
2. 对照正式协议确定真实 AI 修订输出、候选版本和失败恢复边界；不得把 Fixture 直接替换成未经验证的模型响应。
3. 明确云端持久化、版本并发控制和 Cloud Auth 授权后，再设计真实提交适配器。
4. 独立验证组件级批注、移动端真机与大文档性能。
