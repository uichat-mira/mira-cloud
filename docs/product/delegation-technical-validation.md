## 2. 重点方案与降级策略

### 2.1 D03：组件级锚定批注

**目标**：文本、全文和动态组件皆可评论。  
**建议实验**：将结构化 UI 序列化为可验证的组件 schema，每个节点设置稳定的语义 ID 与版本；批注存 `documentVersion + anchorType + anchorId + selectedText(optional)`，不以 DOM path／像素坐标作为唯一真相源。

**验收门槛**：能够跨重排、改名、重生成准确定位或诚实标记为失效。  
**降级**：保留文本／全文批注；组件展示可编辑，但不承诺组件级锚定。

### 2.2 D05：文本与动态 UI Diff

**目标**：新版优先，轻量标记变更，按需比较。  
**实验**：验证 Milkdown Crepe 7.21.2 的 Diff API 与当前 React 包装兼容性；明确其只覆盖文档编辑模型还是能承载需求画布。对动态组件使用字段级差异摘要，不要求像素级 Diff。

**验收门槛**：用户能确认变化来源；缺失映射时明确显示“组件已重新生成”。  
**降级**：先交付版本切换和纯文本 Diff，组件差异以结构化摘要或重生成标记呈现。

### 2.3 D30：动态画布流式重写

**目标**：用户即时看到正文和 UI 随生成更新。  
**关键风险**：模型分片产生半截 JSON、状态倒退、焦点丢失、文本选区漂移、生成中被当作可确认版本。  
**建议路径**：服务端接收 AI 输出并以**经过 schema 校验的完整片段／区块**增量提交；UI 显示流式快照，正式版本与验收状态独立管理。中止时冻结或回到最后可信快照，保留原始接受版本。

**验收门槛**：不中断正常阅读；失败不会损坏已确认内容；最终 schema 校验与正文一致性校验完成前，「接受需求」禁用。

### 2.4 D08：跨会话自动保存

**目标**：刷新、重访、切换设备（如果存在账号关联）可恢复草稿。  
**关键风险**：本地缓存不能替代云端持久化承诺；离线、未授权、乐观并发时不保证同步成功。  
**验证**：先明确数据归属、授权、版本号／乐观锁、待同步标记、失败重试边界。已保存、正在保存、离线待同步、保存失败必须可区分。

### 2.5 D16–D21：长期工作运行契约

**需要核实**：Cloud Pi 当前 Scheduler 的最小周期约束、任务配置版本绑定、暂停恢复、结束后取消在途运行、到期末次报告的触发与交付能力。  
**不应假定**：当前的 Cloud Web 或 Cloud Pi 已经实现 PRD 所要求的全部语义。若运行时不支持，作为独立契约缺口记录，不在前端造一个影子调度器。

特别注意：到期报告的**生成、完成与通知送达**是三个不同事实。需约定截止期限、时区、最后一次执行与交付时间的关系，以及断网／服务故障时的真实错误表达；不能为了声称按时交付而伪造结果。

## 3. 独立验收用例（建议最小集）

1. **正常审阅**：一句话创建长期监测工作 → 初稿 → 3 条锚定批注 → 一次提交 → 流式重写 → 批量确认 2 条、单独处理 1 条 → 逐阶段接受 → 「接受并交代」。
2. **冲突阻断**：正文“每天”、组件“每周”；同步前禁止接受。
3. **回溯**：进入第三阶段后修改已接受的第一阶段，第二、第三阶段原验收失效且需重新确认。
4. **生成失败**：流式一半断网或用户中止；保留可恢复草稿与批注，已接受版本不受损。
5. **重复文本**：文档含多处相同句子，锚点与批注不能串位。
6. **定时无重点**：每小时一次检查，连续多次无重点不通知，但可追溯执行记录。
7. **有期限且暂停**：中途暂停直至到期，仍输出说明实际覆盖缺口的报告并停止新触发。
8. **主动结束**：在途运行被尝试取消；取消中、取消失败、自然完成各有真实状态；不强制生成结案摘要。
9. **移动阅读**：长文选区并打开底部批注，弹出键盘、收起面板、回到原位置，批注不丢失。
10. **越权控件**：模型生成未经允许的发送／删除／付费组件，不可直接执行；显式授权边界仍有效。

## 4. 验收顺序与交付产物

**第一轮：低成本可行性** → TV01、TV02、TV03、TV04、TV05（优先确认最核心的审阅链）。  
**第二轮：技术风险验证** → TV09、TV10、TV11、TV12、TV13（批注、Diff 与响应式）。  
**第三轮：持久化与长期运行契约** → TV06、TV07、TV08、TV14（真实运行事实、时区、期限与成本）。

每个验证项需留下：所用代码版本、实验范围、样例／测试、通过或失败证据、风险与降级方案。原型通过不能冒充生产能力通过。
